# Codex 账号与额度显示实施计划

采用 Superpowers 的实施计划与测试驱动开发流程。

**目标**　在当前 DSH 悬浮窗提供可独立选用的账号套餐和 Codex 剩余额度。

**实现**　OAuth 交换和刷新只提取展示所需的字段。DSH Host 校验本地所有者、读取已有凭据并请求 Codex 额度。客户端复用悬浮窗的内容项生命周期。

[设计](../specs/2026-11-19-codex-subscription-overlay-design.md)

- [x] 先覆盖旧凭据、设备码交换和正常刷新，验证邮箱和套餐投影。增加 `account-profile.mjs`，在 `oauth-wire.mjs` 和 `auth.mjs` 接入。
- [x] 先覆盖只读额度请求、动态时间窗口、暂时失败、取消与换账号，再实现 `subscription.mjs`。通过 Host 的 `subscription` 流发送严格限定的账号或额度数据。
- [x] 扩展保存偏好和 Host/客户端契约，覆盖菜单中两项的独立挂载，以及关闭时停止观察。实现展开和折叠展示。
- [x] 跑完整回归和打包，在已运行的 DSH 里使用现有登录确认账号信息、额度和开关。保留原来的窗口位置和估算项，将两个新增项留在当前窗口。

`0.3.0` 通过 100 项测试。在当前 DSH 使用已有登录验证完整邮箱、套餐及实际返回的 7 天额度窗口。实测了独立勾选、额度读取时间更新、标题栏折叠和重新展开。OAuth 刷新补齐字段通过有缺失字段的合成凭据验证。
