# Codex 参考图编辑与多图输出

本文记录 0.5.0 的设计和验证。当前版本的单图行为见文末。

在现有单张文生图的基础上，让 DSH 模型能引用当前会话的图片进行编辑，也能一次请求多张结果。文字模型继续通过 DSH 工具策略调用已登录账号的 Codex Images 通道。登录、工具权限、账号绑定和请求取消沿用现有实现。

## 调用与图片引用

- 保留 `codex_generate_image`，增加可选的输出张数。新增 `codex_edit_image`，接收编辑描述、参考图引用和可选输出张数。两种操作默认输出一张，本版建议将一次调用的输出张数限制在 1 至 4 张。
- 编辑引用从当前会话中解析。首批可选来源是本轮上传的图片与最近一次成功的 Codex 生图结果，支持按顺序引用其中的图片。读取时使用 DSH 已记录的附件引用并核验图片。图片可作为一张或多张参考发给 Codex `images/edits`。直接上传受当前 DSH 模型的图像输入能力约束，已经生成的会话图片可由工具直接引用。[Codex 编辑请求结构](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/images.rs#L20) · [DSH 附件接口](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/attachment.md)

## 多图输出与补齐

单张请求继续沿用已实测的请求参数。请求多张时，第一笔调用提交指定的 `n`，根据上游实际完成并返回的图片数决定后续动作。官方客户端的请求结构有 `n`，默认工具调用省略该字段。当前插件的真实测试覆盖了省略 `n` 的单图请求，订阅后端收到 `n=2` 时的行为有待实测。[Codex 请求结构](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/images.rs#L5) · [原生工具请求参数](https://github.com/openai/codex/blob/main/codex-rs/ext/image-generation/src/tool.rs#L510)

- 一次返回指定张数时，保存并展示这批图片。明确成功但只返回部分图片时，保留已返回的图片，按缺少的张数逐张请求，直到补齐。补齐编辑图时复用原始参考图和编辑描述。
- 上游明确拒绝张数参数时，可以转为逐张生成。超时、连接中断、限额、取消或账号变化时停止追加。可展示的已完成图片继续保留，并标明实际完成张数。每个请求沿用单次提交保护。
- 工具卡片按生成顺序编号并支持逐张预览和下载。会话记录保存图片引用及实际完成张数。新版卡片继续读取既有的单图记录。

## 验收

- 先用模拟上游覆盖成功返回多张、只返回一张后补齐、补齐途中停止、编辑引用选择、旧单图历史以及两个工具收发的附件边界。
- 在用户当前运行的 DSH 中验收。获得消耗真实额度的授权后，先做一次 `n=2` 的探测并记录首个响应张数，将后端的原生输出与插件自动补齐的结果分别验证。图生图可复用当前会话里的小猫图编辑一次。

## 实机探测记录

2026-11-19，当前 DSH 通过标准 OpenAI API 的 GPT‑6.2 Sol 发起一次工具调用。Codex 订阅端点接受 `n=2`，这次响应包含一张 1536 × 1024 的图片。探测包在首个响应后结束，正式版在同一客户端加载并成功回看了该附件。

随后在同一会话通过 `codex_edit_image` 引用这张图片，将白底改成蓝底。实际订阅请求返回一张 1536 × 1024 的 PNG，并在 DSH 工具卡片显示。

## 0.5.1 单图输出

文生图和图生图每条用户消息最多提交一次 Codex 图片请求，输出一张。工具省略张数参数和补齐流程。图生图支持一张或多张参考图，既有图片记录可预览、下载并继续作为参考图。
